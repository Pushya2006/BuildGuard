# BuildGuard

Automated Software Supply-Chain Evidence and Verification Using SLSA-Aligned CI/CD.

## Status

Project foundation stage. Application and test scaffolding only.

## Setup (Windows PowerShell)

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

## Run the application

```powershell
python app/main.py
```

## Run tests

```powershell
python -m pytest
```

## Build artifact, evidence, and provenance

```powershell
python scripts/build.py
python scripts/generate_provenance.py
```

This produces, in `dist/`:
- `buildguard-artifact.zip` — the build artifact
- `build-evidence.json` — raw build evidence (repo, commit, workflow run, digest, etc.)
- `provenance.json` — SLSA provenance describing the build (see below)

## SLSA Provenance

**What it is:** `scripts/generate_provenance.py` generates an
[in-toto](https://in-toto.io/) Statement whose `predicateType` is
`https://slsa.dev/provenance/v1`, following current
[SLSA](https://slsa.dev/) guidance for describing how a software
artifact was built.

**Why we generate it:** Provenance is the foundation that later
verification and assurance stages of this project will check against.
Without a real, build-derived provenance document, there is nothing
to verify.

**What it records** (populated from `build-evidence.json` and the real
artifact on disk — nothing is hardcoded):
- the artifact's name and independently-recalculated SHA-256 digest
- source repository and commit SHA
- GitHub Actions workflow ref, trigger ref, run ID, and job
- runner OS/architecture
- build/invocation timestamp

When run locally (outside GitHub Actions), GitHub-specific fields
(repository, commit, run ID, etc.) are recorded as `null` rather than
invented, since that information genuinely doesn't exist outside a
GitHub Actions run. The artifact digest is still real and still
verified either way.

**Current project stage:** Provenance **generation** is implemented.
Provenance **verification** (checking a provenance document against
policy, computing an assurance level, detecting unsupported claims,
etc.) is **not yet implemented** and is the next stage of this
project.

**Important — no claims are made here:**
- This project does **not** claim to be "SLSA certified" — SLSA has no
  such certification.
- This project does **not** claim to have achieved any specific SLSA
  build level merely because a provenance document exists.
- This provenance document is generated by this repository's own
  build tooling and is **not cryptographically signed**. It describes
  the build; it does not attest to it via an independent, trusted
  builder.
